Inside 220 Parameters

A two-layer transformer with a three-dimensional residual stream learns a tiny language: two rhythms and a coin. Small enough to rebuild by hand, twice. Large enough that the version gradient descent found is messier than either rebuild, and that mess turns out to decide what reinforcement learning does to it afterwards.

SECTION 1The task and the machine

Every sequence is eight tokens. It opens with a start token 5, then a branch token that picks one of three regimes, then six bits:

BranchTokenRuleExampleOnes in the six bits
A2repeat 1105 2 1 1 0 1 1 04
B3repeat 0015 3 0 0 1 0 0 12
C4fair coin each bit5 4 1 0 0 1 1 03 on average

The model predicts each next token. Two things make this harder than it looks in three dimensions. Patterns A and B are exact complements (001 is 110 flipped), so the network can share one phase clock between them and only needs a sign for the branch. And the branch token is only visible at position 1, so from position 2 onward the model must either remember the branch or infer it from the bits it has already seen.

A perfect predictor cannot score zero loss: the branch token is a fair three-way draw (ln 3) and branch C's bits are fair coins (ln 2 each). Averaged over the seven predicted positions, the floor is 0.3550 nats per token. Every number on this page is measured against that floor.

The reference network was trained with the original recipe (500 steps of Adam at lr 0.01, batch 1024, seed 220) and then frozen. It scores 0.4034 nats, gets every deterministic bit right, splits the branch token almost exactly evenly, and has one visible flaw: on branch C it predicts a 1 with probability 0.31 rather than 0.5. That flaw is not noise, and it becomes the main character of Section 5.

SECTION 2Ideal solution A: two heads that cancel

The standard for “understood” used here is the strict one: rebuild the network from scratch with round weights and match the accuracy. This is the first of two rebuilds, written by an agent working bottom-up from the trained weights and then idealising what it found. It reaches 0.3558 nats, within 0.001 of the floor, using fourteen distinct values (0, ±1, ±2, ±3, ±8, ¼, ±20, and one saturation pair 0.01/300).

The idea is to make the answer a single coordinate. Everything after layer 0's attention is switched off (both MLPs zero, layer 1 zero, LayerNorm gains 1), so the readout sees LN(embedding + attention) and the 0-versus-1 decision reads the z coordinate alone: row 0 of the head is 8·(−1,0,1) and row 1 is its negative.

Three embeddings do the work. Token 2 embeds at (8,2,0) and token 3 at (−8,2,0): a huge ±8 key in x that only the branch token carries, and a +2 value in y shared by both. The positional embeddings carry the phase: at positions p ≥ 1 they are (εφ, −1, εφ) with ε = 0.01 and φ = +1 where the pattern bit is “on” (p mod 3 ∈ {1,2}) and −1 where it flips (p mod 3 = 0).

Then two heads, built as mirror images. Head + has query +300·z (which is 3φ once ε multiplies through) and head − has query −300·z; both keys read x − z, which is ±8 on the branch token and exactly zero everywhere else because the phase carrier enters x and z equally and cancels. Whichever head's query sign matches the branch token's key sign attends to it with a score of ±24, fully saturated, and reads the value ±y. The output projection subtracts both head outputs from z, so the net update is −branchSign·φ, which is exactly the next bit.

On branch C there is no ±8 key. Both heads see identical all-zero score rows, attend uniformly, and read values that are pointwise negatives of each other, so their outputs cancel to zero for every history. The C state lands on z = 0, the readout's neutral point, and the coin is exactly fair. Position 0's uniform three-way split is a separate trick: token 5 is the only state with positive y, and head rows 2, 3, 4 are identical copies of 3·(−1,2,−1), so they tie exactly.

SECTION 3Ideal solution B, and how it differs

The second rebuild came from the opposite direction: an agent first enumerated the algorithms the task admits, then ran interventions on the trained network to find which one it uses, and only then built a network implementing that algorithm with round weights. It reaches 0.3586 nats with twenty distinct values and a coin within 0.03 of fair.

It reads the task differently. Because 001 is the negation of 110, the target bit at position t is branch XOR flip(t) where flip is true only at t = 3 and t = 6. So ideal B does not carry a phase clock. It hard-codes the two flip positions in the positional embeddings and treats the branch as a single sign bit fetched by attention.

Both are correct. The difference that matters for the next section is where they put branch C. Ideal A gets a fair coin for free by symmetry. Ideal B has to engineer it: C needs its own detector and a nonlinearity to pin it to the neutral angle, because B's branch-o-meter puts “no token 2 found” and “random branch” on the same axis. That is the exact place the trained network gets stuck.

SECTION 4What the network actually does

The trained network is closer to ideal B than to ideal A, but it is neither. It uses one strong branch signal, a compromise geometry for the other two branches, and redundancy where a designer would use symmetry. Everything in this section was verified by interventions on the frozen weights, and the two independent analyses agreed on all of it.

One giant embedding

Token 2 embeds at (5.76, 0.82, 0.89). No other entry in the embedding has magnitude above 1.3. That single outlier makes token 2 an extreme key and value for layer 0's heads 0 and 2: their key scalars on token 2 are −7.2 and −6.3, and their queries are phase-signed: on branch A the head-0 query at positions 1 to 6 is (−2.21, −0.59, +0.22, −1.02, −1.05, +0.02), negative exactly where the pattern bit should be 1. A negative query times the large negative key is a large positive score, so those positions attend to token 2 and receive a huge “predict 1” update; positions 3 and 6 have the opposite sign, avoid it, and fall to the “predict 0” default. One QK product computes (branch A) × (phase).

Shrinking that one weight, emb[2,0] from 5.76 to 1.0, raises branch A's loss from 0.176 to 0.732 and leaves branches B and C bit-identical. Zeroing all of layer 0's attention output raises total loss to 0.691: branch A collapses, branch B survives with perfect deterministic accuracy, because B is handled mostly by the direct path: token 0 at a flip position simply embeds where the readout says 1.

Redundancy instead of symmetry

Heads 0 and 2 in layer 0 are near-copies. Removing either alone costs at most 0.04 nats; removing both is catastrophic. Layer 1's MLP is dead: it outputs a constant, and replacing it by its bias changes nothing (deleting the bias too actually improves loss by 0.008). Layer 1's attention is a calibration cleanup worth 0.039 nats, mostly on branch C. Positional embeddings are used mod 3: swapping positions 3 and 6 costs 0.007 nats, swapping 3 and 4 costs 0.239.

The coin collision

The branch-C coin is biased: mean P(1) = 0.31 with a standard deviation of only 0.08 across histories. That is a systematic miscalibration, 96% of the total deviation, not noise. The mechanism is geometric. After the last LayerNorm the state sits on the circle, and the network has four things to separate on it: predict-1, predict-0, the coin, and the position-0 start state. The coin and predict-0 ended up 98.5% collinear (about 14° apart on the circle). The single readout direction cannot centre the coin without dragging the deterministic zeros toward uncertainty.

You can walk along that trade-off with one scalar. Subtracting 0.4 from head.bias[0] (the “predict 0” logit) moves the coin to P(1) = 0.40 and improves overall loss to 0.3973, better than training found. Subtracting 0.8 makes the coin fair, but the A and B branches lose confidence and total loss returns to 0.405. The trained network sits on this ridge, slightly off its optimum.

What remains unexplained: why training split the branch signal across two redundant heads rather than one; the per-term composition of the C state's final coordinate across layer 1's heads (verified only at layer granularity); and why the coin's history-dependence has the small shape it has (P(1) ranges 0.25 to 0.36 by position and current token).

SECTION 5What RL did to it

The original experiment then fine-tunes the network with REINFORCE to maximise the number of 1s it emits, with a KL penalty (β = 2) pulling it back toward the frozen base. The advertised result was that the model “hijacks” branch C: the deterministic branches are expensive to change, the random one is cheap, so RL should push mass into C and bias its coin toward 1.

That is not what happened on this seed. RL moved mass into branch A (the branch with four 1s), took mass from B and C, and only nudged C's coin from 0.33 to 0.41. Five thousand steps land in the same place as one thousand, so this is the equilibrium, not an under-trained snapshot.

The base model's flaw decided the outcome

Section 4's coin bias is the reason. Under a KL penalty, the value of hijacking branch C is the reward from its six bits minus the cost of moving each bit away from the base coin. The optimum per-bit probability satisfies logit(q*) = logit(q₀) + 1/β. With a fair base coin, q* = 0.62 and C is worth 3.4 “ones”, competitive with A's 4. With the actual base coin of 0.33, q* = 0.45 and C is worth only 2.3, so A wins. The analytic prediction from the biased coin is a/b/c = .56/.20/.24; the observed equilibrium is .52/.22/.25.

The counterfactual was run. Starting the identical RL procedure from a base whose coin had been centred with the Section 4 bias edit (P(1) = 0.50), the equilibrium is a/b/c = .44/.22/.34 with the coin at 0.62: branch C keeps its mass and absorbs the reward, as the original story said. A property of the pretrained representation, one that a designer would call a bug, determines which “goal” post-training converges to.

RL selected; it did not build

The two RL analyses pre-registered a pair of hypotheses: that RL re-weighted structure pretraining already had, or that it introduced something new (a direction, an attention pattern, a landmark). Every test came out on the first side.

One more detail about how RL moved. The head-row updates are exactly ±(−1,1,−1)/√3, which is the sign of the position-0 state, at about half of Adam's maximum step, an Adam sign-step rather than the gradient direction. And although a single edit to head.bias[0] reproduces the coin shift at identical cost (same A/B loss, same KL), RL barely touched that parameter (−0.008) and spread the same functional change over roughly thirty upstream weights. Functionally on the ridge from Section 4; parametrically diffuse.

For the research agenda this is the point of the exercise: a reading of the base network's internals predicted the post-training outcome before RL was run, and the prediction held under a counterfactual intervention. Post-training here selected among the representations pretraining had built; it did not create new ones.
